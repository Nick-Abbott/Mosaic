# Mosaic 0.3.0

Mosaic 0.3.0 ships the runtime (`mosaic-core`, `mosaic-test`, and `mosaic-bom`) together with optional Canvas contract analysis. Runtime users continue to compose tiles and use Canvas without a Mosaic build plugin or KSP processor.

## Highlights

- The optional `org.buildmosaic.analysis` Gradle plugin checks configured application roots for Canvas requirements. `APPLICATION` mode verifies roots; `LIBRARY` mode exports a complete contract for downstream verification.
- `STANDARD` enforcement fails proven missing bindings and reports unverifiable paths. `STRICT` also fails on unverifiable paths.
- Extraction runs inside the normal Kotlin compilation and updates affected sources incrementally. The assembly task packages a complete summary in the resulting JAR. No separate production K2 compiler process is launched.
- The compiler and Gradle plugin, plus the analysis support library, are available as same-version artifacts. The Gradle plugin resolves its matching compiler artifact automatically.
- Runtime documentation now distinguishes explicit parallel composition, request-scoped caching, and caller-owned Canvas cleanup. Low-level dependency provider and compiler extraction classes are no longer Kotlin source API.

## Installation and limits

See the [runtime quick start](../../README.md) and [analysis plugin guide](../../mosaic-gradle-plugin/README.md). Analysis is optional. Its supported boundary is pure Kotlin/JVM `main` sources with Kotlin Gradle plugin and compiler **2.2.10 only**; KSP and framework project layouts are outside that boundary. Runtime Canvas lookup remains available without analysis.
